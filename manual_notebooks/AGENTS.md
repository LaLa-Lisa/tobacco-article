# Архитектура моделей и бэкендов

Эти инструкции действуют для `manual_notebooks/` и всех вложенных каталогов.
Описание пользовательского сценария и примеры находятся в [README.md](README.md).

## Назначение и границы

Ноутбуки задают параметры эксперимента и показывают результаты. Повторно
используемая логика скачивания, обучения и предсказания находится в `scripts/`.
Архитектура состоит из реестра моделей, адаптеров провайдеров и небольшой фабрики.
Не переносите вызовы SDK провайдеров в общий код выбора моделей или в ноутбуки.

Сейчас реализован только `ultralytics`. Для будущих интеграций предусмотрены
`mmdetection` и `rfdetr`. Другие бэкенды не входят в согласованный план:
соответствующие модели сохраняются в каталоге отключёнными, с поясняющими
комментариями. Не добавляйте зависимости и фиктивные реализации будущих бэкендов.

## Карта модулей

| Модуль | Ответственность |
| --- | --- |
| `scripts/common.py` | Общие пути, словарь выбора `MODELS`, публичный доступ к реестру |
| `scripts/registry.py` | `MODELS_REGESTRY`, метаданные реализаций, проверка согласованности ключей |
| `scripts/contracts.py` | Структуры данных и протоколы `Backend` и `Predictor` |
| `scripts/backends/__init__.py` | Фабрика `get_backend(spec)` |
| `scripts/backends/ultralytics.py` | Скачивание, обучение, загрузка, подсказки и нормализация результатов Ultralytics |
| `scripts/workflows.py` | Выбор включённых моделей, последовательное обучение, отчёт о пропусках и загрузка выбранных артефактов |
| `scripts/weight.py` | Проверка наличия весов, пакетное скачивание, таблицы для ноутбуков |
| `tests/test_models.py` | Автономные тесты с имитациями провайдера и временными файлами |

## Выбор моделей и реестр

- `common.MODELS` — единственный словарь включения и отключения моделей. Не заменяйте его списком `SELECTED_MODELS` и не вводите параллельный источник выбора.
- `MODELS_REGESTRY` использует те же ключи. Это согласованное имя публичного API; не исправляйте его написание попутно с другими изменениями.
- `ModelSpec` описывает конкретную реализацию: идентификатор, бэкенд, задачу, конструктор, файл весов, операции и причину недоступности.
- Бэкенд обозначает программную реализацию, а не автора или семейство архитектур. Не считайте все YOLO совместимыми с Ultralytics.
- Семейства без конкретного файла весов остаются неготовыми к запуску. Не выбирайте размер модели автоматически.
- Имя файла весов задаётся явно: например, `yolov12n` соответствует `yolo12n.pt`. Не восстанавливайте его простым добавлением `.pt` к идентификатору.
- При добавлении модели обновляйте и `MODELS`, и реестр. Сохраняйте проверку совпадения ключей, идентификаторов и булевых флагов.
- Импорт каталога и проверка наличия файлов не должны загружать Ultralytics, PyTorch или другие SDK провайдеров.

## Контракты и поток выполнения

Общий поток: `MODELS` → `ModelSpec` → `get_backend(spec)` → операция адаптера.

Адаптер реализует протокол `Backend`:

```python
download(spec) -> ModelArtifacts
train(spec, initial, dataset, config) -> TrainingRun
load(spec, artifacts, device) -> Predictor
```

Объект `Predictor` предоставляет `predict(image, *, prompts=None, **options)`
и возвращает список `Prediction`. Загруженная модель переиспользуется между
вызовами; не загружайте веса заново для каждого изображения.

- Используйте `ModelArtifacts` для путей к весам и необязательной конфигурации. Не возвращайте наружу только внутренний объект SDK.
- Общие параметры обучения находятся в `TrainConfig`, параметры конкретного провайдера — в `options`. Не приписывайте одинаковую семантику настройкам разных библиотек.
- Проверяйте совместимость задачи модели и весов до запуска обучения. Проверку датасета выполняет провайдер при обучении. Текущий `DatasetSpec` описывает локальный YAML YOLO с задачей `detect` или `segment`.
- Адаптер переводит вызовы и результаты между общим интерфейсом и SDK. Отображение таблиц pandas/IPython остаётся в слое для ноутбуков.
- Нормализованные результаты содержат массивы NumPy на CPU. Рамки `xyxy` и булевы маски используют координаты исходного изображения; `native` сохраняет исходный результат провайдера.
- Не назначайте семантические классы маскам, полученным без классификации: для них `class_ids` и `names` равны `None`.
- Текущий API обрабатывает отдельные изображения: локальный путь, PIL или массив H×W×3 `uint8` в BGR. Сопровождение объектов на видео с сохранением состояния в этот интерфейс не входит.
- Подсказки зависят от модели. SAM3 использует отдельные интерфейсы для интерактивных точек/рамок и поиска по тексту/примерам объектов. Не направляйте все варианты в один универсальный вызов.

## Доступность, ошибки и артефакты

- Наличие предсказания не означает наличие обучения. В текущем адаптере SAM, MobileSAM, SAM2, SAM3 и FastSAM поддерживают только скачивание и предсказание.
- Пакетное скачивание проверяет все включённые записи до начала загрузок. Существующие файлы переиспользуются; новые скачиваются во временный каталог, чтобы прерванная загрузка не считалась готовыми весами.
- `train_models` сообщает о неподдерживаемых моделях и пропускает их. Для обнаруженной до обучения недоступности используйте `UnsupportedOperation`.
- Некорректные данные и непредвиденные ошибки обучения останавливают выполнение. Не превращайте произвольные исключения в молчаливые пропуски.
- Каждый запуск получает отдельный каталог в `RUNS_DIR`, лучшие и последние веса и `manifest.json`. Сохраняйте идентичность модели, хеш исходных весов, версию провайдера, заданные и фактические параметры, описание датасета и метрики.
- `weights/trained/<model-id>.pt` — удобная копия последних успешных весов. Для воспроизводимого предсказания используйте артефакт конкретного запуска.
- `load_model` принимает явно выбранные артефакты. Не подменяйте отсутствующие обученные веса предобученными.
- Сохраняйте совместимость `weight.inspect_weights()` и `weight.download_weights(return_paths=...)`. При `return_paths=True` возвращается словарь идентификаторов и путей; иначе — `None`.

## Как добавлять будущий бэкенд

При явной задаче на интеграцию MMDetection или RF-DETR:

1. Добавьте модуль адаптера в `scripts/backends/`, реализующий существующие контракты, и подключите его в фабрике. Импорт SDK должен оставаться отложенным.
2. Обновите `ModelSpec.unavailable_reason`: сейчас он явно допускает только `ultralytics`. Одного изменения фабрики недостаточно.
3. Укажите реальные варианты, файлы весов, конфигурации и поддерживаемые операции в реестре. Уберите отметку о недоступности только у реализованных записей.
4. Проверьте текущие предположения общего кода: `DatasetSpec` и адаптер Ultralytics ориентированы на YAML YOLO, а `weight.py` использует текущую схему локальных путей. Адаптируйте эти границы, если новому провайдеру нужен другой формат или несколько артефактов.
5. При преобразовании датасета сохраняйте состав train/val/test и соответствие классов. Не создавайте новые случайные разбиения внутри адаптера.
6. Нормализуйте результаты в `Prediction` и добавьте тесты нового маршрута через фабрику, обработки ошибок, артефактов и выходных координат.

Не создавайте отдельный класс для каждого размера модели, если различия можно
выразить метаданными одного адаптера.

## Проверка изменений

Из корня репозитория:

```bash
.venv-notebooks/bin/python -m unittest discover -s manual_notebooks/tests -v
```

Для изменений логики проверяйте затронутые сценарии: реестр, маршрутизацию,
переиспользование и сбои скачивания, пропуски обучения, артефакты запусков,
совместимость разметки, подсказки и координаты результатов.
При изменении ноутбука проверяйте JSON и синтаксис ячеек с учётом IPython-магии.
Не перезаписывайте существующие пользовательские изменения и исторические результаты.

Автономные тесты не требуют GPU, скачивания весов или полного обучения.
Проверку с реальным SDK проводите на доступных локальных весах и явно отделяйте
её результат от тестов с имитациями. Не запускайте длительное обучение только
ради проверки обычного изменения адаптера.

## Язык

Описания в Markdown, README, комментарии и docstrings пишите на русском.
Сообщения выполнения, ошибки, статусы, заголовки таблиц и подписи графиков —
на английском. Поле `ModelSpec.note` также выводится пользователю и должно быть
на английском. Имена API, ключи данных и входные текстовые подсказки моделей
не переводите ради языка документации.
