# Протокол разбиения датасета для обучения детектора табака

Процедура реализована в [07_prepare_yolo_split.ipynb](../dataset_notebooks/07_prepare_yolo_split.ipynb)
для набора `data/tobacco_migrated`. Разбиение формируется заново на уровне
отдельных изображений и не использует номера съёмочных кампаний, прежние
обучающие выборки или сведения из `migration_manifest.json`.

На момент подготовки этой заметки алгоритм проверен на текущем наборе без
записи результатов; файлы разбиения и `data.yaml` ещё не созданы. Ниже описан
реализованный протокол и состав выборок при параметрах по умолчанию,
а не результаты проведённого обучения.

## Исходные данные и контроль разметки

Единицей разбиения является файл изображения с соответствующим текстовым
файлом разметки YOLO. Текущий набор содержит 2 508 изображений и столько же
файлов разметки. Для детекции используется единственный класс `0: tobacco`.
Семантические маски и COCO-аннотации при формировании этого разбиения
не используются.

Перед разделением проверяются уникальность имён изображений без расширения,
наличие парных файлов разметки и формат каждой непустой строки: идентификатор
класса и четыре нормированные координаты ограничивающей рамки. Проверяются
допустимость класса, конечность координат, принадлежность координат диапазону
[0, 1] и положительные ширина и высота. Эти проверки характеризуют корректность
формата, но не подтверждают точность аннотирования. Девять изображений
с пустыми файлами разметки сохраняются в наборе как примеры без размеченных
объектов целевого класса.

## Алгоритм формирования выборок

Список файлов из каталога `images/` сначала сортируется по пути, после чего
перемешивается генератором стандартной библиотеки Python:
`random.Random(42).shuffle(images)`. Используется локальный генератор
с фиксированным начальным значением `seed = 42`. Стратификация по числу
объектов, наличию пустой разметки или иным характеристикам не выполняется.

Заданные доли обучающей и валидационной выборок составляют 0,8 и 0,1.
Для общего числа изображений N размеры определяются как
`N_train = floor(0.8 × N)`, `N_val = floor(0.1 × N)` и
`N_test = N − N_train − N_val`. Первые `N_train` элементов перемешанного
списка образуют обучающую выборку, следующие `N_val` — валидационную,
остальные — тестовую. Остаток округления относится к тестовой выборке.

| Выборка | Число изображений | Фактическая доля |
| --- | ---: | ---: |
| Обучающая | 2 006 | 79,98% |
| Валидационная | 250 | 9,97% |
| Тестовая | 252 | 10,05% |
| Всего | 2 508 | 100,00% |

Каждый путь изображения включается ровно в одну выборку. Проверка на текущем
наборе подтвердила отсутствие пересечений по путям, полное покрытие исходного
списка и воспроизводимость назначения при повторном выполнении с теми же
параметрами. Обучающая выборка предназначена для оптимизации параметров
модели, валидационная — для выбора контрольной точки и настройки эксперимента.
Тестовую выборку следует использовать только для итоговой оценки после
фиксации модели и настроек; наличие её пути в YAML само по себе не означает,
что итоговое тестирование уже выполнено.

## Сохранение и воспроизводимость

При запуске с `RUN_SPLIT = True` ноутбук записывает `train.txt`, `val.txt`
и `test.txt` со списками изображений, `data.yaml` с абсолютным корнем датасета,
ссылками на эти списки и именем класса, а также `split_summary.json`.
Последний содержит метод разбиения, seed, заданные доли, фактические размеры,
число пустых файлов разметки и полный состав каждой выборки. Изображения
и аннотации не перемещаются и не изменяются. Перезапись существующих
результатов требует `OVERWRITE = True`.

Для сравнения моделей необходимо использовать одни и те же сохранённые
списки. Seed сам по себе не фиксирует эксперимент: изменение состава
изображений меняет результат разбиения. Следует сохранять также версию
ноутбука, версию Python и неизменную копию изображений и разметки;
`split_summary.json` не содержит контрольных сумм их содержимого.
После переноса набора на другую машину требуется актуализировать абсолютный
путь в YAML, сохранив состав выборок.

## Ограничения интерпретации

Разбиение обеспечивает непересечение файловых путей, но не гарантирует
независимость сцен. Группировка по исходным кадрам, пространственной близости,
кампаниям или совпадению пиксельного содержимого не выполняется. Связанные
фрагменты одного кадра либо визуально близкие изображения могут оказаться
в разных выборках. Поэтому такой протокол оценивает качество на случайно
отложенных изображениях данного набора и не позволяет сам по себе сделать
вывод о переносимости на новые поля, съёмочные кампании или условия съёмки.
Сходство обучающих и тестовых сцен может приводить к более высокой оценке
качества, чем при независимом разделении по источникам съёмки.
