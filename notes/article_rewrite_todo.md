# План новой статьи: практичное выделение сорняков с защитой табака

Основание: [ответы на вопросы](../local/article_rewrite_questions.md), комментарии в
[исходном черновике](../tobacco-article-tmp/article.tex), материалы репозитория
и [статья — источник датасета](original_article.pdf). План составлен 20.11.2026.
Статус обновлён 20.11.2026 после текстовой переработки статьи. Отметка [x] означает
завершённый конкретный текстовый результат, а не проведённый эксперимент.
Наличие черновика метода или протокола не означает реализации и валидации.

## Замысел и результат

Разработать и проверить практичный конвейер **детекция табака → защитная область
→ HSV-маска растительности → маска сорняков**. Выбрать сочетание модели,
настроек и реализации по качеству итоговой маски, скорости и памяти на доступном
оборудовании. Основной результат — измеренный компромисс между найденными
сорняками и пикселями табака, ошибочно оставленными в маске сорняков.

Рабочий заголовок: *Efficient Crop-Aware Weed Segmentation in Tobacco Images
Using Object Detection and Adaptive Vegetation Thresholding*. Слово *Adaptive*
оставить в итоговом названии только при наличии соответствующего результата.
Цель публикации — MDPI; конкретный журнал пока не выбран.

Вклад статьи строится вокруг трёх связанных частей:

1. Проверенный набор масок и рамок целых растений, пригодный для независимой оценки.
2. Экономичный гибридный метод и обучение детектора с повышенным штрафом за
   недостаточное покрытие табака; сравнение с простыми способами защиты растений.
3. Общий эксперимент по качеству, FPS и памяти, включая Jetson, с наглядным
   выбором рабочих конфигураций.

Статья заканчивается получением маски сорняков. Координаты воздействия, стебли,
лазер, физическое повреждение растений и конкретный робот в эксперименты не входят.
Данные пока состоят из фотографий: обработку последовательности изображений
можно измерять, но нельзя выдавать за проверку качества на реальном видео.
Старые результаты на 110 изображениях не используются как baseline новой статьи.

## 3. Собрать единый конвейер и оценщик

- [ ] Реализовать общий путь предсказания: изображение → рамки табака → объединённая
  защитная область → HSV-растительность → вычитание защиты → итоговая бинарная
  маска сорняков. Порог уверенности, расширение рамок, HSV и очистку маски хранить
  в конфигурации; возвращать маски в исходное разрешение.
- [ ] Сохранить выходы промежуточных этапов, чтобы отдельно видеть пропущенный
  табак, сорняки внутри защитных рамок и ошибки самого HSV.
- [ ] Реализовать один оценщик итоговой маски для всех моделей. Основные метрики:

  | Метрика | Определение и назначение |
  | --- | --- |
  | Weed IoU | Пересечение предсказанной и эталонной масок сорняков / их объединение |
  | Weed precision / recall | Доля настоящих сорняков в выданной маске / доля найденных эталонных пикселей сорняков |
  | Crop→weed error | `|P_weed ∩ G_crop| / |G_crop|`: доля пикселей табака, ошибочно разрешённых как сорняк |
  | Потери сорняков в защите | `|G_weed ∩ P_protection| / |G_weed|`: цена защитных областей |

  Дополнительно считать долю табака вне защитной области: HSV может случайно
  скрыть ошибку детектора, и это нужно видеть отдельно. mAP и recall рамок
  оставить диагностикой, а не главным основанием выбора системы.
- [ ] Зафиксировать обработку пустых масок и `ignore`, числители и знаменатели,
  агрегирование по пикселям и результаты по кампаниям. Не скрывать отсутствие
  сорняков или табака за произвольным значением метрики.
- [ ] Подготовить одинаковые визуальные панели: исходник, эталон, защитные рамки,
  маска сорняков, пропущенные сорняки и ошибочно включённый табак. Сохранить
  заранее выбранную подборку обычных и сложных примеров.
- [ ] Проверить оценщик на небольших примерах с известным результатом, а также
  обратное преобразование координат, пустые предсказания и объединение рамок.

**Критерий готовности:** любое сравниваемое решение выдаёт одну и ту же форму
результата и оценивается одинаково. «Незадетый табак» означает геометрическое
сохранение пикселей в разметке, а не доказанное отсутствие физического повреждения.

## 5. Проверить два улучшения предложенного метода

### Основной эксперимент: обучение для полного покрытия табака

- [ ] Исследовать существующие асимметричные функции потерь и выбрать проверяемую
  формулировку. Рабочая гипотеза: дополнить штатный box loss штрафом за стороны
  предсказанной рамки, которые проходят внутри GT-рамки и оставляют часть растения
  снаружи. Нормировать ошибки по размеру GT; штатный loss должен сдерживать
  неограниченное расширение рамок.
- [ ] Разделить две причины ошибки: недостаточный размер найденной рамки и
  полностью пропущенное растение. Добавка к регрессии сопоставленных рамок
  сама по себе не решает вторую проблему; проверить назначения и диагностику пропусков.
- [ ] Реализовать добавку сначала для одной выбранной YOLO-конфигурации через
  адаптер/trainer, записывать формулу и коэффициенты в манифест.
  Проверить направление штрафа и градиенты на искусственных рамках.
- [ ] Сравнить при одинаковых исходных весах и бюджете: штатное обучение;
  штатное обучение с настройкой confidence и расширения рамок;
  custom loss с такой же возможностью настройки постобработки.
  Использовать малую заранее заданную сетку коэффициентов на validation.
- [ ] Измерить изменение Crop→weed error вместе с Weed recall/IoU и потерями
  сорняков в защитных областях. Оставить отрицательный результат в анализе,
  если custom loss не даёт преимущества перед простой настройкой.

Confidence здесь — порог выдачи предсказаний. Его снижение при оценке не
описывать как изменение функции потерь или способ обучения.

## Порядок и ограничение вычислительного бюджета

Основная зависимость: **постановка → доверенная разметка и split → оценщик
и конвейер → ресурсный фильтр → обучение → абляции → финальная оценка → текст**.
Обзор, MMDetection и заготовку структуры статьи можно готовить до завершения
разметки; основные обучающие запуски требуют готового датасета.

Рабочая трактовка ограничения «2–3 дня GPU» — максимум **72 суммарных GPU-часа**,
включая использование обеих карт. Одновременная работа двух GPU расходует два
GPU-часа за час. Это бюджет планирования, а не прогноз длительности обучения.

| Работа | Верхний ориентир, GPU-ч |
| --- | ---: |
| Пилот разметки, выбранная генерация масок, проверка интеграций и ресурсный фильтр | 10 |
| Основное обучение короткого списка | 24 |
| Custom loss и повтор ключевого сравнения | 12 |
| Пилот адаптивного HSV и сегментационный контроль | 6 |
| Итоговые измерения и оценка | 8 |
| Резерв на сбои и необходимый повтор | 12 |
| **Максимум** | **72** |

- [ ] После короткого запуска оценить стоимость эпохи и всей матрицы; вести журнал
  расхода GPU-времени. При превышении сократить число моделей, размеров и
  коэффициентов, сохранив одинаковые условия ключевых сравнений.
- [ ] Не расходовать бюджет на длительное дообучение SAM, широкий поиск
  гиперпараметров и полную поддержку всех моделей MMDetection.
- [ ] Отдельно оценить календарное время ручной проверки данных: оно не входит
  в GPU-бюджет и может определять срок всей работы.
